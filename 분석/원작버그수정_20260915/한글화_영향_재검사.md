# 네 버그 수정의 기존 한글화 영향 재검사

검사일: 2026-09-15. 사용자 요청에 따라 실제 현재 한글화판·개조판을 변경 전 백업과 다시 비교했다. 이번에는 ROM이나 빌드 소스를 수정하지 않았다.

## 결론

**파일과 코드 검사 범위에서는 기존 한글화와 충돌한 부분이 없다.** 다만 실제 에뮬레이터에서 모든 관련 장면을 실행한 것은 아니므로, 게임 전체에서 문제가 없다고 100% 보장하는 단계는 아니다.

## 새로 확인한 내용

| 확인 대상 | 결과 |
|---|---|
| 기존 한글화 코드와 새 수정 구간 | 겹침 0곳. 버그 코드 구간 전체를 검사했다. |
| 글꼴·화면 그림 | 두 판 모두 변경 전과 완전히 같음. |
| 대사·이름·메뉴 등 저장된 문자열 조각 | 중복 포함 158,679개 동일. 차이는 별도 요청으로 고친 메사이안 소드 수치 118곳뿐. |
| 레온 음성 수정 | 압축 해제 후 음성 번호 두 바이트만 다름. 나머지 장면 명령 동일. |
| 시나리오별 시작 위치와 길이 | 모두 유지됨. 내부 자식 위치는 재압축 길이에 맞춰 표가 다시 작성됨. |
| 여신·보류 중인 상성 안내 세 블록 | 파일 내용까지 동일. |
| 용병 함수가 한글 출력 공간을 덮는지 | 기존 84바이트 함수 구간만 사용. 다른 공간을 빌리지 않음. |
| 옛 함수 주소를 부르는 다른 곳 | 직접 주소 참조는 교체한 호출 목록 두 곳뿐. 근처 직접 분기와 외부의 상대주소 상수 읽기에서도 추가 참조 없음. |
| 용병 코드의 처리 결과 | 제공된 타인 패치와 현재 우리 ROM의 실제 명령을 해석해 비교. 입력 1,200세트 × 함수 2개 = 2,400회 기록 결과 일치. |
| 호출한 쪽으로 돌아간 뒤 | 이어지는 코드가 필요한 값을 다시 읽는지, 보존할 값이 유지되는지 확인. |
| 현재 빌드 기록 | 입력 파일과 현재 첫 트랙의 지문 일치. |

용병 함수의 비교에는 인물 번호 0~19, 항목 번호·증가량·기존값의 다양한 바이트 값을 사용했다. 메모리에 기록된 결과뿐 아니라 보존해야 하는 실행용 값도 비교했다. 검사기는 이 두 함수가 사용하는 명령만 해석하는 작은 검사 도구이며, 실제 새턴이나 에뮬레이터 전체 실행을 대신하지는 않는다.

직접 주소·분기 검사는 확인 가능한 코드 경로에 대한 검사다. 실행 중 계산되는 알려지지 않은 경로까지 없다고 증명한 것은 아니다.

## 실제 게임에서 남은 확인

- 에그베르트 관련 장면을 지난 뒤 퇴각 횟수.
- 고용 증가를 얻은 뒤 해당 인물의 고용 수와 한글 고용 화면.
- 에스트·오스트의 엘레멘탈 목록과 선택 시 한글 표시.
- 시나리오 10 발가스 격퇴 뒤 레온 음성과 한글 대사의 진행.

검사 결과로 볼 때 한글화가 깨질 징후는 없다. 위 장면의 실제 실행을 확인하면 파일 검사만으로 남는 불확실성을 더 줄일 수 있다. 게임 화면 이동은 기존 규칙대로 사용자가 맡는다.
