## 카타카나 처리 방침 (핵심 결정)
- **content-patch(글리프 내용 교체)**: 공유 안 된 카타카나만(アイテム=아이템 ✓). 공유된 것(シ/ー/ナリオ 등)은 다른 화면 깨짐.
- **tilemap 리다이렉트(정석, 깊은 RE)**: 빈 VRAM에 한글 글리프 추가 + 각 라벨의 charno 소스를 새 글리프로 돌림. res#29는 256/256 꽉 차 여유공간 없음 → 별도 VRAM/리소스 확보 + 화면별 타일맵 소스 RE 필요. **큰 작업.**
- **현실 절충**: 한자 라벨 전부 한글(대부분 완료) + 공유 안 된 카타카나(アイテム) 한글 + 공유 카타카나는 유지 or 리다이렉트.

# ▶ 다음 세션 착수 가이드 — 카타카나 리다이렉트 (플랜A, 사용자 승인)

## 왜 리다이렉트인가 (내용교체 불가 이유)
1. **공유**: シ(res#29 g6) 하나가 ショップ(쇼)·シナリオ(시)에 공유 → 내용 바꾸면 한쪽 깨짐(실측: シ→상 하니 제목이 "상ナリオ", 되돌림).
2. **결합/장음**: **ョ·ッ·ェ·ー**는 혼자 음절이 안 되고 앞글자와 결합(シ+ョ=쇼, ゲ+ー=게-, ッ=받침). → **칸 수 ≠ 한글 음절 수**(ショップ 4칸 → "상점" 2음절). 칸별 교체 원천 불가.
∴ **카타카나 슬롯을 한글로 재활용 + 라벨의 글리프 지정(매핑)을 새 글리프로 돌림**이 유일 해법.

## 지금까지 확인된 사실 (중복조사 금지)
- 라벨 charno는 **런타임 계산**(리소스 VRAM 로드베이스 + 글리프인덱스). LANG1.BIN에 charno 고정테이블 **없음**(검색 0건).
- ショップ/シナリオ/アイテム는 **SJIS 문자열로 저장 안 됨**(0.BIN/LANG1/LANG2 검색 0건) → 문자열 기반 렌더 아님.
- res#29 **256/256 꽉 참**(빈 글리프 슬롯 0) → 새 공간 없이 카타카나 슬롯 재활용해야 함.
- **VRAM 타일맵 write BP는 안 걸림**(DMA 기입, 실측).

## 착수 절차
1. `launch(replace=true, content=build/disc-krpoc/langrisser-krpoc.cue)` → `load_state build/ep1_scen1_battleprep.state`
2. **워크램 타일맵 섀도에 write BP**: 알려진 섀도 `0x060a55a0`(= workramh 오프셋 `0xa55a0`; 세션5 RE "8px 렌더러가 타일번호를 타일맵 섀도 0x060a55a0에 기입"). → `set_breakpoint(kind=write, memory_type=workramh, start=0xa5000, end=0xa6000)`
3. 메뉴 재draw 유발(뒤로가기 `b` / 서브메뉴 진입) → BP 히트 → **PC 포착**
4. 그 PC에서 역추적: 코드가 **어느 글리프 인덱스를 어디서 읽어** 섀도에 쓰는지 → **라벨↔글리프 지정 소스** 특정
5. 그 소스를 한글 글리프 인덱스로 패치 + 카타카나 슬롯에 한글 렌더(`gen_menu_kr_all.syl_tiles`) → 재압축/삽입
6. **검증**: 시나리오 제목·상점·게임·데이터메시지 등 카타카나 쓰는 화면 전부 콜드부트로 확인(깨짐 0 확인 필수)

## ⚠ 실기 검증 함정
- 세이브스테이트/기존 세션은 부팅 시점 VRAM이라 패치가 안 보임 → **콜드부트(launch replace)** 필수.
- 글리프 공유 때문에 한 곳 고치면 다른 화면이 깨질 수 있음 → 바꾼 글리프가 쓰이는 **모든 화면**을 확인.

# ★★ 세션6 돌파: 라벨→글리프 인덱스 테이블 발견 (실기 확증) ★★

## 결론: ASM 훅 불필요. **평문 데이터 테이블 1개만 패치하면 리다이렉트 완료.**

### 테이블 위치
| 위치 | 주소 |
|---|---|
| 워크램(Ep1 런타임) | `workramh 0x742C0` (= SH2 `0x060742C0`) |
| **디스크 track1.bin (Ep1)** | **`0xE7030`** |
| **디스크 track1.bin (Ep2)** | **`0x15BB48`** |
| 워크램↔디스크(Ep1) 델타 | `+0x72D70` |

두 사본은 테이블 내용이 바이트 동일하고 뒤따르는 포인터 값만 다름(Ep1/Ep2 프로그램 빌드).

### 구조: **6바이트 고정 슬롯 × 라벨**, 값 = res#29 글리프 인덱스, `0x70` = **빈칸**
```
0x742C0 / disc 0xE7030:
  0f 10 0d 11 70 70   兵士配属    (15,16,13,17)
  00 01 02 03 04 05   アイテム装備 (0-5)
  0a 0b 0c 0d 0e 70   指揮官配置   (10-14)
  1b 1c 70 70 70 70   出撃        (27,28)
```
카탈로그 res#29 인덱스와 4개 라벨 전부 일치. 배틀프렙 메인 메뉴 = 정확히 이 4줄.

### 실기 확증 (추측 아님)
`write_memory(workramh 0x742C0, "1b1c707070707070")` → `b`로 재draw:
- 1행 `兵士配属` → **`出撃`으로 바뀜** ✓
- 2행 `アイテム装備` → **`(빈칸)(빈칸)テム装備`** ✓ (0x70=빈칸 확증)
- 3·4행 무변화 ✓
→ **테이블이 라벨을 전적으로 지배함. 0x70=빈칸.** (확인 후 원복함)

### 왜 이게 카타카나 문제를 푸는가
- **칸수≠음절수 해결**: 슬롯이 6바이트 고정이고 남으면 `0x70`으로 패딩 → ショップ(4글리프) → **상점(2글리프)+70×4** 로 그냥 됨. ョ/ッ/ー 결합 문제 소멸.
- **공유 글리프 회피 가능**: 라벨이 쓰는 글리프를 *선택*할 수 있으므로, 공유된 슬롯(シ=g6 등)은 **건드리지 않고** 그 라벨의 비공유 슬롯(ョ=g7, ッ=g8, プ=g9)에 한글을 렌더한 뒤 테이블을 `07 08 70 70 70 70`처럼 돌리면 シナリオ는 그대로 살아있음.
  → 즉 **content-patch + 테이블 리다이렉트 조합**이 정답. 새 VRAM 공간 확보 불필요(res#29 256/256 꽉 참이 더 이상 걸림돌 아님).

### 카탈로그 기존 서술 중 **틀린 것 (정정)**
- ✗ "타일맵 섀도 = `0x060a55a0`" → **배틀프렙 메뉴엔 해당 없음**(그 영역 전부 0). 그 섀도는 대화창(8px 렌더러) 전용. 이 주소에 write BP 걸면 **안 걸린다**(세션6 실측).
- ✗ "charno 고정테이블 없음" → charno 테이블은 없는 게 맞지만 **글리프 인덱스 테이블은 있다**(위). 디스크에서 charno가 아니라 **인덱스 시퀀스**로 검색해야 찾힌다.
- ✗ "VRAM 타일맵 write BP 안 걸림 → 막다른 길" → 애초에 타일맵을 쫓을 필요가 없다. 인덱스 테이블이 소스다.

### 관측된 렌더 사실 (배틀프렙, Ep1)
- 메뉴 텍스트 레이어 = **NBG3** (스크롤 0,0). NBG1=창 배경(단일 charno 평면), NBG0=맵.
- 라벨의 charno는 **글리프당 4씩 연속**(2x2 셀): `▶`=0x42a, 兵=0x42e, 士=0x432, 配=0x436, 属=0x43a.
  → VRAM엔 **그 화면에 필요한 글리프만 라벨 순서대로 packed 복사**됨(전 뱅크 상주 아님).
- NBG3 PNT 섀도 버퍼(워크램): `0x9FFBC` / `0xA01FC` / `0xA0C3C` / `0xA0E7C` 클러스터. (참고용 — 패치엔 불필요)

## ★ 전역 글리프 인덱스 공간 해독 (세션6 후반, 확정)

테이블 값은 res#29 로컬 인덱스가 아니라 **전 뱅크 통합 인덱스**다:

| 값 범위 | 뱅크 |
|---|---|
| `0x00`–`0x3F` (0–63) | **res#29** |
| `0x40`–`0x7F` (64–127) | **res#30** (로컬 = 값−64) |
| `0x80`–`0xBF` (128–191) | **res#31** (로컬 = 값−128) |

**증거(디코드 일치)**
- `2c 40 40` = **OFF** → O=res#29 g44, F=**res#30 g0** ← 뱅크 경계 확증
- `49 2f 4a` = **ロード** → res#30 g9(카탈로그 `口`는 오독, 실은 **ロ**), ー=res#29 g47, res#30 g10(ド)
- `41 42 31 32` = **表示設定** → res#30 g1(表)·g2(示) + res#29 g49·g50
- `3c 3d 06 2f 3f` = **戦闘シーン** → res#29 60,61 + シ(6)·ー(47)·ン(63)

**∴ `0x70` = 112 = res#30 g48 = 카탈로그가 `48 (blank)`이라 적어둔 그 빈칸 글리프.** (특수 마커가 아님)

### 카탈로그 res#29 판독 오류 정정
- `62 ラ` → 실은 **ブ** (`36 2f 3e` = セーブ)
- `54 せ` → 실은 **セ**
- `32 ス` → 실은 **ズ** (フェイ**ズ**終了)
- res#30 `9 口` → 실은 **ロ**

3. 시스템 메뉴 테이블은 워크램 존재만 확인, **라이브 화면 확증 미실시**(배틀 진입 필요).

## 전역 인덱스 공간 — 확증 범위
- **확증**: `0x00-0x3F`=res#29, `0x40-0x7F`=res#30. (`OFF`=`2c 40 40`, `ロード`=`49 2f 4a`, `表示`=`41 42`, `0x70`=res#30 g48 빈칸)
- **미확증**: `0x80-0xBF`=res#31 은 **대칭 추정일 뿐**. 발견된 두 테이블의 값이 **전부 `0x71` 이하**라
  res#31을 참조하는 실례가 하나도 없다. `8e8f0890`(ユニット) 워크램 검색 0건도 이와 일치.
  → **유력 해석: 6B 슬롯 테이블 체계는 res#29+res#30만 다루고, res#31 라벨(방어/최대/적/유닛)은 다른 서브시스템**
  (실제로 배틀 커맨드는 테이블이 아니라 글리프 내용만 패치해서 한글화했다).
