# 원작 버그 4건 적용 및 아이템 설명 조사

## 완료 결과

2026-09-15 사용자 요청으로 랑그릿사 2의 다음 수정들을 기본 한글 패치에 포함했다. 개조판도 새 한글화 결과를 받아 같은 수정이 들어 있다.

1. 퇴각 횟수를 늘리는 조건 수정.
2. 용병 고용 증가량을 현재 인물에게 기록하도록 수정.
3. 고용 목록에 엘레멘탈까지 포함되도록 검사 범위 확대.
4. 시나리오 10에서 발가스 격퇴 후 레온 대사의 음성 참조 번호 수정.

크라운·룬스톤·가격·상점 개조는 계속 개조판에만 있다. 이름 볼드 수정이나 타인 패치의 숨겨진 상점 목록 변경은 가져오지 않았다.

## 유지보수 방법

- 소스: `scripts/bugfixes_l2.py`.
- `scripts/reinsert_text.py`가 대사 삽입 후 장면 데이터를 고치고, 한글 BIN 생성 후 세 가지 코드 수정을 적용한다.
- 기본 한글화 전체 빌드를 하면 항상 반영된다. `translation-manifest.json`의 `base_bugfixes`에 네 항목을 기록한다.
- 한글화 빌드 후 개조 빌드를 하면 그대로 상속된다. 개조 폴더에 버그 수정 코드를 복제하지 않는다.
- `scripts/verify_base_fixes.py`가 최종 글꼴 처리까지 끝난 디스크의 수정 상태를 확인한다.

용병 수정 방식은 9월 16일 다시 고쳤다. 현재 빌드는 원래 값 설정·증가 함수(`LANG2.BIN 0x178C4–0x17917`)를 그대로 둔다. 증가 명령 `4A 06 02`만 빈 영역 `0x65B00–0x65BFF`의 별도 코드로 보내고, 나머지 증가 명령은 원래 함수로 보낸다. 자세한 이유와 검사는 아래 9월 16일 기록에 있다.

레온 음성은 압축을 푼 장면 데이터 `0x577`의 두 바이트만 `C202 → 7609`로 바꾸었다. 우리 압축기로 재압축하면 8바이트 늘며, 같은 시나리오 안의 빈 공간을 8바이트 줄여 시나리오 전체 위치와 길이를 유지한다.

예상한 원본 코드나 장면 내용이 아니면 빌드를 중단한다. 새로운 번역 코드와 충돌한 상태로 조용히 덮어쓰지 않는다.

## 메사이얀소드: 수치는 있었지만 끝 숫자가 다음 줄로 밀림

일본어 원문과 우리 빌드 모두 공격력 −4, 방어력 −3, 공격 수정치 −2를 포함하고 있었다. 다만 우리 설명의 마지막 `２` 앞에 줄바꿈 명령이 들어 있었다. **모든 수치가 사라진다는 제보 전체를 게임 화면에서 재현한 것은 아니지만**, 한 줄이어야 할 수치가 두 줄이 되는 문제는 파일에서 확인했다.

수치 줄을 `AT-4 DF-3 A수정-2`로 줄였다. 띄어쓰기가 반 칸인 현재 방식에서 14칸이므로 자동 줄바꿈 없이 들어간다.

수정 후 설명 전체:

```text
손잡이에 말과 별 문양의
촌스러운 검. 효과 불명.
AT-4 DF-3 A수정-2
```

랑그릿사 1·2의 일반 아이템 설명 118곳에 적용했다. 이전부터 동결한 여신·상성 안내 블록 세 곳은 기존 자료를 그대로 남겼다. 이름 표기는 기존 `메사이얀소드`를 유지한다. ‘효과 불명’은 원문의 표현이며, 경험치 효과를 새로 설명하는 변경은 하지 않았다.

## 홀리로드: 원문부터 수치가 없는 설명

일본어 원문의 마지막 줄은 `魔法能力が上昇`이고 우리 번역은 `마법능력이 상승`이다. 숫자가 번역 과정에서 빠진 것은 아니다. 같은 이름을 가진 두 종류 모두 설명 방식이 같다.

현재 설명 전체는 그대로 유지했다:

```text
성검 랑그릿사의 힘을 여는
열쇠가 되는 빛의 로드.
마법능력이 상승
```

실제 데이터에 들어 있는 효과는 랑그릿사 1·2 모두 다음과 같다.

| 효과 | 값 |
|---|---:|
| 마법 사정거리 | +2 |
| 마법 위력 | +1 |
| 마법 내성 | +30 |

L2 효과 표의 아이템 12·13(0부터 센 번호), L1의 동일한 효과 배열을 대조했다. 홀리로드의 능력치나 설명문은 이번에 변경하지 않았다.

## 2026-09-16: 캐릭터 메이킹 A/D 수정치 회귀 재조사

사용자 확인 결과는 다음과 같다. 같은 워록 메이킹 선택에서 8월 29일 `KR v1.2`는
정상이고, 9월 15일 한글화판은 7/7이며, 첫 수정판
`Langrisser_KR_20260916_ADfix.chd`는 2/0이었다. 첫 수정판을 정상판이라고
안내한 것은 화면 확인 없이 코드 모의 검사만 믿은 잘못된 판단이다. **이 파일은 사용하지 않는다.**

네 원작 버그 수정 중 메이킹에 영향을 준 부분은 `hire-increase`이다. 장면 명령
`4A`는 용병 수뿐 아니라 메이킹의 A수정(항목 7)·D수정(항목 8)에도 쓰인다.
9월 15일 코드는 모든 항목의 기존 값이 3보다 작으면 3으로 올렸다. 메이킹의
증가량 2/4가 5/7로 바뀌어 워록 기본값 2/0과 합쳐진 7/7 현상과 맞는다.
첫 수정은 항목 6에만 최솟값 3을 적용했으나, **나머지 항목도 기록할 인물 위치를
원래 방식과 다르게 계산**했다. 메이킹 시점에는 이 차이로 A/D 증가분이 결과
인물에게 반영되지 않아 2/0이 나온 것으로 분석된다.

현재 수정은 원래 두 함수를 바이트 단위로 그대로 보존한다. `4A 06 02`(용병 수
+2)만 별도 코드로 보내며, 나머지는 모두 원래 증가 함수로 이동한다. 메이킹
장면 블록 98의 명령 데이터에는 `4A 07 01`·`4A 08 01`이 있고 `4A 06 02`는 없다.
그러므로 메이킹 명령은 모두 원래 계산 경로를 사용한다. 별도 코드는 원본에서
모두 0이었던 `LANG2.BIN 0x65B00–0x65BFF`를 사용하고, 용병 증가 명령의 호출
주소 한 곳(`0x63834`)만 새 코드로 돌린다. 퇴각·엘레멘탈·레온 음성 수정은 유지했다.

기계어를 실행하는 검사 7개가 통과했다. 모든 일반 증가 명령을 원래 함수와
비교했고, 메이킹 A/D 증가분 2/4와 용병 수 +2도 검사했다. 한글화·개조 빌드,
최종 디스크 검사, 두 CHD의 무결성 검사도 통과했다. 직전 개조 빌드와 비교해
바뀐 디스크 구역 3곳은 모두 `LANG2.BIN` 안이다. 빌드 직후에는 실제 게임
화면을 확인하지 못했으므로 파일명을 검증 후보로 표시했다.

- 한글화 검증 후보: `한글화/build/Langrisser_KR_20260916_quizfix_candidate.chd`
- 개조 검증 후보: `개조/build/disc-mod/langrisser-mod.chd`
- 잘못된 첫 수정판: `한글화/build/Langrisser_KR_20260916_ADfix.chd`(사용 금지)
- 9월 15일판: `한글화/build/Langrisser_KR_20260915.chd`(7/7 재현 비교용)

### 사용자 화면 확인

두 CHD를 프로젝트의 `1.3V` 폴더에 한글판·개조판으로 복사한 뒤, 사용자가
메이킹 결과에서 **A수정 4 / D수정 4**를 직접 확인했다고 알렸다. 확인한 파일이
한글판인지 개조판인지는 아직 특정되지 않았으므로, 두 판 모두 화면 확인을
