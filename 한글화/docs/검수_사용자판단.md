# 검수 — 사용자 판단이 필요한 항목

세션24부터 L1·L2 전 시나리오를 자동 검수하면서, **내가 임의로 정하면 안 되는 것**을 여기 모은다.
기계적으로 확실한 것(표준어·어절 잘림·페이지 초과·존대/평어)은 내가 고치고 여기엔 안 적는다.

각 항목은 `[ ]` 미결 / `[x]` 결정됨. 결정되면 **결정 내용을 그 줄에 적고** 반영한다.

## 6. dedup 공유 때문에 못 고친 것 (세션24 블록6)
한 문자열이 여러 시나리오에 쓰여 **한쪽만 고칠 수 없는** 항목. 원문 대조로는 고쳐야 맞지만,
다른 장면에서 어떻게 읽히는지 확인이 필요하다.
- [ ] `L2:6/2/5#136` **`[NAME:03]…부탁한다.`** → 원문은 `{09:03}‥‥。`(이름만). **'부탁한다'가 원문에 없다.**
      2곳에서 공유 중.
- [x] **해결됨** — 전역 스캔으로 같은 패턴 **12엔트리 / 74곳**을 찾아 일괄 교정했다.
      원문이 `{이름}‥‥。`(이름을 부르고 말끝을 흐리는 연출)인데 번역이 `부탁한다`·`그래`·
      `실례하겠습니다`를 지어 붙이고 있었다. **dedup은 원문이 같은 것끼리 묶이므로**
      한 번 고치면 모든 사용처에서 옳다.
      검출법: 원문에서 `\{[^}]*\}|<..>` 를 지운 결과가 `‥…。、` 뿐인데 번역에 한글이 있는 엔트리.
- [ ] `L2:7/2/5#49` 정령 지문이 원문 2p → 번역 3p. **2곳 공유**라 못 고쳤다(다른 장면 확인 필요).

## 7. 선택지 지문의 문투가 갈려 있다 (세션24 블록12에서 발견)
원문은 전부 `〜ますか？`(정중)인데 번역이 세 갈래로 갈렸다. 게임 내내 같은 상황(조사·획득
선택지)이라 하나로 통일하는 게 맞아 보인다.
```
마셔 보겠는가?        L2:12/2/5#29 #31 (각 5곳 공유)  · L2:6/2/5#56 '먹어 보겠는가?'
마셔볼까요?           L2:0/2/5#33 #36
찾아보시겠습니까?     L2:11/2/5#25 · L2:5/2/5#30 '눌러 보시겠습니까?'
```
- [ ] 어느 쪽으로 통일할지 결정 필요. 원문이 정중체이므로 **`~보시겠습니까?`** 를 권한다.
      ⚠ dedup으로 여러 곳이 묶여 있어 한 번에 바뀐다(폭 변화 있으니 재검증 필요).

## 9. 세션24 자율 검수 중 내가 정한 것 — 사후 확인 바람

### 9-1. `光輝の末裔` = **빛의 후예**로 전역 통일 (블록24에서 발견)
번역이 두 갈래로 갈려 있었다. **「빛의 후예」 136엔트리 vs 「광휘의 후예」 43엔트리.**
다수파인 **`빛의 후예`** 로 43엔트리를 흡수했다(전체 170엔트리).
- ⚠ `光輝` 자체는 다른 자리에서 **「광휘」**로 옮겨져 있다(`광휘의 힘`, 나레이션 `광휘를 다스리는 성검`,
  `광휘에 인도되는 자`). 즉 `光輝`=광휘 / `光輝の末裔`=빛의 후예 로 갈라 쓰는 셈이다.
- [ ] 이대로 둘지, 아니면 **`광휘의 후예`로 통일**할지 판단 필요. 되돌리려면 반대로 치환하면 된다
      (폭이 1.5칸 늘어나므로 재조판·재검증 필요).

### 9-2. 몬스터(카타카나) 말투 — 쉼표 남발을 걷어냈다 (블록24)
원문이 카타카나로 어눌하게 말하는 연출(`ドコヘ行クツモリダ？`)인데, 번역이 쉼표를 마구 박아
**어절 한가운데를 끊고** 있었다: `도망, 칠 수` · `끝, 나지 않, 았나` · `서둘, 러라` · `기다, 리신다`.
→ **어절 경계는 지키고**, 딱딱함은 조사를 덜고 문장을 짧게 잘라 살리는 쪽으로 고쳤다.
- [ ] 어눌함이 더 드러나야 한다면 다른 장치(예: 종결어미 `-다` 고정, 조사 생략)를 쓸 수 있다.
- ⛔ 이 과정에서 `L2:24/2/5#8` 이 **의문문을 평서문으로 바꾼 오역**임을 발견해 고쳤다
      (`逃ゲラレルト思ッテイルノカ？` → 「도망칠 수 없다」 였던 것).

### 9-3. ⛔ **페이지 경계 어긋남** — 새 검사 도구를 만들었다 (세션24)
`[PAGE]`는 조판이 아니라 **음성 재생 구간의 경계**다. 그런데 페이지 **수**만 맞고
경계가 밀린 항목이 전역에 있었다. `audit_pages.py`는 수만 보므로 못 잡는다.

실제로 나온 유형:
- `L2:49/2/5#8` — 원문 p4(「でも、これからは光輝の末裔として、使命を果たすつもりです」)를
  앞 페이지에 합치고 **p4 자리를 `…` 하나로 채워** 수만 맞춰 놓았다.
- `L2:42/2/5#101` — 원문 p3(「他の者も、逃げるが良い…」)이 **통째로 빠지고**
  p2를 둘로 쪼개 수만 맞췄다.
- `L2:53/2/5#117` · `L2:79/2/5#114` · `L2:63/2/5#74` · `L2:14/2/5#57` — 경계가 한 칸씩 밀림.
- `L1:15/2/5#8` — 원문 p2(「！？」)가 사라지고 「그리고」가 독립 페이지가 되어 있었다.

→ **`python scripts/audit_pagebreak.py [tag] [block]`** 신설. 원문/번역의 페이지별 분량
  비율을 견주어 어긋난 곳을 찾는다. 8엔트리를 우선 교정했고, **남은 후보 29건**은
  각 장을 검수할 때 함께 본다(짧은 페이지는 한국어가 자연히 짧아져 생기는 오탐이 섞여 있다).

### 9-4. 블록58에서 남긴 것
- [ ] **`さらば‥‥友よ。`(L2:58 #71 #72, 4곳 공유)** — 「…안녕히 …벗이여.」였던 것을
      **「…잘 있게…[NL]벗이여.」**로 고쳤다. `さらば`는 **떠나는 쪽**이 쓰는 작별이라
      죽어가는 키스의 말로 읽었기 때문이다. 만약 남은 자(레스터)가 키스를 보내는 말이라면
      **「…잘 가게…[NL]벗이여.」**가 맞다. → 게임 화면에서 초상화 확인이 필요하다.
- [ ] **리아나가 이 장에서만 반말이다** — `#89` 「어째서 변해버린 거야?」 · `#91` 「넌 상냥하고…」
      · `#93` 「역시 바뀌고 말았어…」. 4절에서 **리아나=존댓말**로 확정했는데, 엘윈과 적으로
      갈라선 이 장면은 원문도 `〜の？`·`〜だわ` 보통체이고 번역도 통째로 반말이다.
      감정이 무너진 장면이라 의도된 것으로 보아 **손대지 않았다.** 존댓말로 되돌릴지 판단 필요.
      (같은 대사가 여러 분기에 공유되므로 한 번에 바뀐다.)
- [x] `#105` **페이지 경계 어긋남** — 원문은 `はっ！`가 p2의 머리인데 번역이 p1 꼬리에 붙여
      「보젤의 부하가 있다니…… 헛!」로 만들어 놓았다. 음성 구간이 밀리므로 갈라 놓았다.
- [x] `#50` **페이지 초과** — 원문 1페이지(3줄)인데 4줄이 되어 2페이지로 밀렸다.
      「리아나 님, 제시카 님을 모시고 여기서 탈출해 주십시오!」 →
      「리아나 님과 제시카 님을 모시고 탈출하십시오!」로 줄여 1페이지로 되돌렸다.

### 9-5. 블록59에서 남긴 것
- [x] **전각 영문 `ＭＵＵＮ‥‥`(#60)가 음차되지 않고 남아 있었다** → 「무우운……」.
      바로 옆 `ＧＵＵ`(#59)·`ＫＳＹＡＡＡ`(#61)는 이미 음차되어 있어서 **하나만 빠진** 자리다.
      2절의 「전각 영문 154곳」(ＮＰＣ·ＡＴ 등 UI 약어)과는 성격이 다르다 — 이건 **울음소리**라
      음차가 명백히 옳다. 같은 유형이 더 있는지 전역 스캔이 필요하다.
- [x] **주문의 중점 `・`이 반각 공백으로 흩어져 있었다** — `#2`(알하자드 해방 주문)와

## 9-70. ⛔ **정정** — `借りを返させてもらう` 를 잘못 읽었다 (9-55 · 9-56 · 9-57 취소)

`〜させてもらう` 는 사역형이지만 **화자 자신의 행동을 말하는 겸양 관용구**다
(`説明させてもらう`=설명하겠다 · `帰らせてもらう`=돌아가겠다). 사역을 문자 그대로
「~하게 해주마」로 옮기면 **주체가 상대로 뒤집힌다.**

`この借りは返させてもらう` = **「이 빚은 (내가) 갚겠다」** = 설욕하겠다는 선언이다.

같은 코퍼스에 **정답 형태가 이미 있었다** — `L2:16 #36` `この借りは、必ず返すぞ！`
→ 「이 빚은 반드시 갚겠다!」. 이쪽에 맞춰 세 곳을 되돌렸다.

| 위치 | 원문 | 잘못 고친 것 | 되돌림 |
|---|---|---|---|
| L1:4 `#49` | `いずれ返してもらうぞ` | 언젠가 **갚게 해주마** | 언젠가 **갚아주마** |
| L1:5 `#24` | `必ず返させてもらうわ` | 반드시 **갚게 해주겠다** | 반드시 **갚아주겠다** |
| L1:6 `#13` | `この前のかりは返させてもらう` | **갚게 해주마** | **갚아주마** |

**교훈**: `〜させてもらう`/`〜てもらう` 는 사역·수수 형태만 보고 주체를 판단하면 안 된다.
문맥(누가 누구에게 설욕하는가)과 **같은 뜻의 다른 표현이 코퍼스에 어떻게 옮겨져 있는지**를
먼저 확인할 것.

(`どのデータをロード\x04 5 \x00`). 원본 SCEN에서 문자열 앞을 보면 답이 나온다:

```
L2:102 (0x40A246)  … 00 00 12 98 | 00 00 15 84 | 00 00 | 98 4C ど の デ …
L2:103 (0x3FE8B6)  … 00 00 09 f8 | 00 00 12 98 | 00 00 | 95 60 ど の デ …
L2:104 (0x427912)  … 00 00 12 98 | 00 00 13 08 | 00 00 | 95 D0 ど の デ …
                                                          ↑↑↑↑↑ 廊/描/片 으로 읽힌 2바이트
```

앞이 전부 `00 00 <2바이트 코드>` 반복 배열이다. 덤퍼도 `#11`~`#17` 은 이미
`{09:f8}`·`<12><98>`·`<15><84>` 처럼 **raw 제어 코드**로 표기하고 있다.
`#19` 만 뒤따르는 문자열과 붙어 있어서 글자로 해석됐을 뿐이다.

⛔ **이 3자는 지우면 안 된다.** 지우면 제어 바이트가 사라진다. 한자로 두는 편이 원본 바이트를
보존한다(재인코딩 시 같은 바이트로 복원).

### ③ 진짜 로드 문구는 이미 따로 있다

```
どのデータをロードしますか？   → 「로드할 데이터는?」   (2,0) UI 리프 · L1·L2 전 120블록 공유
描/廊/片どのデータをロード      → 리프 2 · L2:101·103·105 / 102 / 104   ← しますか？ 가 잘린 사본
```

리프도 다르고 `しますか？` 가 잘려 있다. 실제 화면에는 정본 쪽이 나온다.
**사용자 결정: 한자 유지 + 뒷부분만 교정.** 같은 원문을 두 가지로 옮기지 않도록
문구는 정본에 맞췄다 → **`描로드할 데이터는` · `廊로드할 데이터는` · `片로드할 데이터는`**


## 9-73. `重装騎兵` ↔ `重装機兵` 말장난 (L2:71) — 현행 유지 (세션24)

『重装機兵ヴァルケン』(1992) 패러디 퀴즈다. **문제 자체가 낚시**다.

```
#34  さあ、問題だぁ！重装騎兵と言えば？        ← 騎(말)로 출제
#35~#37  선택지: 何、それ？ / ヴァルケン / ヴァルケソ    ← 정답은 가짜인 「ヴァルケソ」
#38  せ、正解‥‥。¶ 重装騎兵ではなく、重装機兵だと見破るとは さすがだ。
```

**사용자 결정: 한자 병기도 재창작도 하지 않는다.** 다만 원문 한자를 그대로 옮기면
「중장기병이 아니라 중장기병이라고 간파하다니」가 되어 문장이 파탄난다. 현재 번역은
이미 병기도 재창작도 아닌 **설명적 의역**이라 그대로 둔다 —
`저, 정답… ¶ 말 타는 기병이 아니라 / 로봇 쪽임을 간파하다니, / 대단하군.`

## 9-75. ⛔⛔ **`{05}`는 0폭 제어코드가 아니라 1칸 들여쓰기다** (세션24, 사용자 실기 발견)

사용자가 **L2 4장(블록3) 나레이션 첫 줄이 "앞에 공백 때문에 살짝 넘어간다"** 고 지적해
드러난 조판기 버그다. `kr_markup._atom_width` 가 `[C:xx]` 를 일괄 0칸으로 반환하고 있었다.

### 실측 — 원문에서 역산
나레이션 원문(L1·L2 전체)의 줄을 `{05}` 로 시작하는 것과 아닌 것으로 갈라 폭 분포를 냈다:

```
{05} 없는 줄 (1191줄)   최대 16.0칸   ← 128줄이 정확히 16칸 = 나레이션 창 폭
{05} 있는 줄  (921줄)   최대 15.0칸   ← 117줄이 15칸. 16칸은 2줄(0.22%)뿐 = 노이즈
```

**`{05}` = 1칸.** 그래서 `{05}` 로 시작하는 줄의 실질 한계는 **15칸**이다.
제목 줄의 `{05}` 개수가 제목 길이에 반비례하는 것도 같은 근거다(가운데 정렬용 들여쓰기).

### 영향 — 나레이션 89건이 창 폭 초과
조판기가 0칸으로 셌으므로 15.5~16.0칸 줄을 통과시켰고, 실제로는 16.5~17.0칸이 됐다.
사용자가 본 4장은 `L2:3/2/7#0` p2 L1 = `빛의 대신전은 겉보기보다 손상이`(15.5+1=16.5칸).

### 수정 — 나레이션 리프에만 적용
`indent_w` 파라미터를 뚫고 **`(2,7)` 나레이션에서만 `[C:05]`=1칸**으로 센다.
전역 적용은 **`L2:100` 상성표 7건**(`[C:05]` 를 칸 정렬용으로 여러 개 씀 · 동결·보류)과
대사 2건까지 재조판시켜 위험하다.

| 파일 | 변경 |
|---|---|
| `scripts/kr_markup.py` | `_atom_width`/`rewrap_markup`/`line_widths`/`max_line_width` 에 `indent_w=0.0` |
| `scripts/reinsert_text.py` | `iw = 1.0 if (is_narr and not is_goddess_block) else 0.0` |
| `scripts/dump_scenario_kr.py` | `geometry()` 가 `indent_w` 를 돌려주고 `laid_out()` 이 전달 |
| `scripts/verify_disc_layout.py` | `pages_of(..., indent_w)` — **검증 도구도 같은 버그였다** |

**결과: 초과 89건 → 0건.** 나레이션 페이지가 6건 늘었지만 나레이션 페이지 증가는 허용
규칙이다(5절). 여신 동결·`L2:100` 은 영향 없음(검증 통과).

⚠ **되돌리려면** `reinsert_text` 의 `iw` 를 0.0으로 (상수 하나).
⚠ **교훈**: 원문이 지키는 제약은 원문에서 역산해 확인할 수 있다. `{05}` 처럼 "제어코드처럼
생긴 것"이 실제로 폭을 먹는지 의심하라. **검증 도구가 같은 가정을 공유하면 회귀를 못 잡는다.**
